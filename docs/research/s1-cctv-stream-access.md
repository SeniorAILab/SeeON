## 핵심 판정

**에스원은 일반 고객용 공개 상품으로 raw video stream을 제공한다고 확인되지
않는다.** 공개 고객 문서(제품 페이지·FAQ·자료실)는 웹뷰어·모바일뷰어·PC뷰어·
검색·재생·백업(다운로드) 중심. "불가능"이 아니라 **"일반 고객 공개 문서상
미공개, 엔터프라이즈/SI 경로는 가능성 높음"**이 정확한 표현.

## 에스원 — 확인된 사실

| 근거 | 내용 |
|---|---|
| CCTV 소개 페이지 | NVR/DVR을 "저장, 검색 및 원격 조회 기능" 중심으로 설명 |
| FAQ | "언제 어디서나 영상 조회" — PC는 에스원 웹뷰어, 모바일은 S1 모바일뷰어 |
| 자료실 | 웹뷰어·모바일뷰어·PC뷰어·클라우드 CCTV 매뉴얼로 구성 |
| 영문 Access Control 페이지 | 다이어그램에 "Video Viewer(RTSP)" 명시, "open platform design", S-1 SVMS 연동 언급 — **엔터프라이즈 문맥** |
| KRX 공시 | "개방형 SVMS 연동 플랫폼", "SVMS 연동 판매를 원하는 **업체** 대상 개방형 SDK 제공" — 파트너/SI 경로 |
| 영상정보처리방침 | 24시간 촬영, 촬영일로부터 30일 보관, 접근권한자 지정, 목적 외 이용·제3자 제공 기록, 만료 후 영구 삭제 |

- 인증 방식(Basic/Digest/ONVIF 계정 구조): 공개 문서상 불명.
- 동시 접속 제한: 에스원 문서엔 미명시. OEM 협력사(한화비전·IDIS·WebGate)
  장비 사양 기준으로 확인 필요 (예: 한화비전 NVR `Live Unicast 10`).
- 클라우드 저장소의 서버 레벨 export API: 불명 (UX 레벨 다운로드만 확인).

## 법적 함의 (전제 3 체크리스트에 추가됨)

에스원이 영상정보 처리 수탁자 구조라면, 시설 측 서버에서의 AI 분석이
'제3자 제공' 또는 '처리 위탁 범위 변경'에 해당하는지 검토 필요. 개인정보
포털 고정형 영상정보처리기기 가이드라인상 CCTV 영상의 제3자 제공·열람은
원칙적으로 제한.

## 대안 벤더 비교 (직송 적합성)

기준: 고객이 자기 서버에서 장비에 직접 인증해 영상을 받아 실시간 분석에
넣을 수 있는가. 전통 CCTV 장비의 주류 인터페이스는 RTSP/ONVIF/HTTP API/SDK
(HLS는 게이트웨이/변환 계층 역할).

| 벤더 | 공개 인터페이스 | 직송 적합성 |
|---|---|---|
| Axis | RTSP API, VAPIX(open API), ACAP SDK, event stream, MQTT·webhooks | 매우 높음 |
| 한화비전 | RTSP, ONVIF S/G/T/M, SUNAPI(HTTP API), SDK/CGI, MQTT | 높음 |
| WebGate | RTSP/RTP, ONVIF Profile S, WESP SDK | 높음 |
| Hikvision | RTSP, ONVIF, ISAPI, SDK (OpenAPI는 파트너 지향) | 높음 |
| Dahua | RTSP, ONVIF(S/T/G), CGI, SDK, 일부 RTMP | 높음 |
| IDIS | RTP/RTSP, ONVIF Profile S, DirectIP (SDK는 파트너 포털) | 중상 |

참고: 에스원 OEM 협력사가 한화비전·IDIS·WebGate — 즉 **에스원 설치 장비도
장비 차원에서는 RTSP를 지원할 가능성이 높으나**, 관리 계정 소유와 계약
조건이 별도 관문.

## 실무 옵션 (보고서의 권고 구조)

1. 에스원 유지 + SI/파트너 경로 협의 — 계약 협상 의존, 일정·비용 불확실.
2. 고객 소유 NVR/카메라로 별도 표준 스트림 확보 — 예측 가능, 책임 이동.
3. 현장 엣지 게이트웨이 추가 — 인터넷 노출 최소화, 박스 관리 부담.
4. 클라우드 VMS·이벤트 API 우선 — 이벤트 자동화엔 적합, raw stream 아님.

운영 주의: "RTSP 지원" 확인만으론 부족 — 동시 세션 수·대역폭·서브스트림·
메타데이터 채널(영상과 별도)을 모델 단위로 재확인할 것.
